# Stage 3D — nine-class dataset recovery and feasibility

Decision date: 2026-10-19. **The implementation objective remains nine-class EG-VAN.** This report supersedes the earlier suggestion of a seven-class implementation fallback in `NINE_CLASS_DATASET_SUITABILITY_DECISION.md`. It is a provenance and feasibility decision, not a final dataset manifest, split, preprocessing run, or model experiment. No images or original audit CSVs were changed; no image dataset was downloaded.

## 1. Fanconic version and paper provenance

The [EG-VAN paper, §IV-A](https://www.researchgate.net/publication/390831641_EG-VAN_A_Global_and_Local_Attention_based_Dual-Branch_Ensemble_Network_with_Advanced_color_balancing_for_Multi-Class_Skin_Cancer_Recognition) describes a benign/malignant collection of over 3,200 images and cites [45] and [54]. [Reference 45](https://www.sciencedirect.com/science/article/abs/pii/S0010482524008837) explicitly identifies [Fanconic, *Skin Cancer: Malignant vs. Benign*](https://www.kaggle.com/datasets/fanconic/skin-cancer-malignant-vs-benign), accessed 20 November 2023. [Reference 54](https://www.sciencedirect.com/science/article/pii/S095741742301549X) describes combining HAM10000 with a malignant/benign dataset, but its accessible text does not identify a versioned image list. The EG-VAN paper itself gives no Fanconic version number, exact binary image assignments, per-image IDs, or duplicate policy.

On 2026-10-19, a **metadata-only** read of Kaggle's public [dataset view API](https://www.kaggle.com/api/v1/datasets/view/fanconic/skin-cancer-malignant-vs-benign) returned `currentVersionNumber=4`, `lastUpdated=2019-06-19T21:51:11.657Z`, `totalBytes=171612705`, `licenseName=Unknown`, owner **Claudio Fanconi**, and version-4 notes: *“New data set, which is split in train and test set.”* The response exposed only version 4 in its `versions` array; timestamps, content and availability for versions 1–3 were **not established**. Version 4 predates the cited paper's 2023 access date, which makes it a plausible source version, but does not prove which version EG-VAN used. The version notes establish that the train/test organization is publisher supplied; they do not establish that EG-VAN respected it.

Kaggle's description calls the collection processed ISIC Archive pictures. It claims “two folders with each 1800 pictures (224x244),” which disagrees with its own published structure and the observed 1,800/1,497 images at 224×224. Treat that prose as inaccurate, not image-level clinical provenance. The dataset has **no published ISIC image-ID map or patient/lesion identifiers in the retrieved metadata**. `licenseName=Unknown`; the uploader says rights are bound to the [ISIC Archive](https://www.isic-archive.com/) and advises against monetization. The [ISIC Archive FAQ](https://www.isic-archive.com/blank-1) says underlying licenses are set per image. Neither the uploader's warning nor the EG-VAN paper's CC BY article license is a complete per-image license record.

The public Kaggle [file-list API](https://www.kaggle.com/api/v1/datasets/list/fanconic/skin-cancer-malignant-vs-benign) was read in 33 metadata pages (`pageSize=200`). It listed **6,594 unique file paths**: 3,297 under `data/` and a mirrored 3,297 under top-level `train/` and `test/`. The paths total 343,225,410 bytes across both trees. **All 6,594 path names and individual byte sizes match the current local `data/isic/` files**, with zero missing, extra, or size-mismatched entries; the local canonical `data/isic/data/` tree totals **171,612,705 bytes**, exactly Kaggle's reported `totalBytes`. The sorted public `name,size` listing has SHA-256 `7a201f33b916f2ed141d53b67877dac3938b97f96e9b1250b9797c4e72dbcbdb` when encoded as UTF-8 lines `name,size` joined by `\n`. This is a **strong metadata-level match to the current version-4 listing**, much stronger than matching class counts alone. Kaggle's listing exposes no per-file cryptographic checksums; byte identity with remote version 4 and exact paper-version identity are therefore still unverified. No file contents were fetched from Kaggle.

The local canonical tree is `data/isic/data/{train,test}/{benign,malignant}/`: 1,440/1,197 source-train benign/malignant and 360/300 source-test benign/malignant. The mirror is never extra data. There is no local original Kaggle archive, download receipt, README, license file, source ISIC ID table, or patient/lesion metadata. Numeric basenames are not source IDs. The v4 file-list match supports the package provenance; it cannot recover clinical labels, original ISIC IDs, per-image rights, or EG-VAN's actual split membership.

## 2. Retained BENIGN review gate

The current [completion summary](../analysis/nine_class_overlap_completion/completion_summary.json) and [proposed exclusion ledger](../analysis/nine_class_overlap_completion/proposed_binary_exclusions.csv) give **2,369 proposed binary exclusions**, leaving an *upper bound* of **83 BENIGN** and **845 MALIGNANT** records. The 83 split into **64 publisher train** and **19 publisher test**. The 425 unresolved priority pairs and 760-pair focused queue remain unchanged by this report.

The new [83-record benign review plan](../analysis/nine_class_recovery/benign_review_plan.csv) was derived from retained benign paths and the existing [focused queue](../analysis/nine_class_overlap_completion/human_review_queue.csv). Each row records the full binary path, its strongest unresolved HAM candidate path, HAM `dx` and verified HAM lesion ID, pHash/dHash distances, native-binary-size pixel MAE and correlation, coarse correlation, candidate count, two additional candidate paths where present, publisher split, proposed conditional decision, and `not_human_reviewed` status. The full 760-pair queue and the broad batch CSVs remain the complete pair evidence; this 83-row file is a **bounded review schedule, not a sample manifest or adjudication ledger**.

Every one of the 83 currently retained BENIGN images has a focused candidate against a HAM **`nv`** image. For each image's strongest candidate, Pearson correlation is **0.99612777–0.99893552**, pixel MAE is **0.442137–3.573076/255**, and **67 of 83** have both perceptual hash distances zero. These are compelling same-photograph *candidates*, but none satisfied the audit's strict automatic pixel rule of correlation ≥0.999 together with MAE ≤2/255; none is marked human-reviewed or newly excluded here. The narrow margin below a threshold is not evidence of independence. If a reviewer confirms all 83 as HAM copies, **zero** local BENIGN records would remain; this is a conditional scenario, not an adjudicated count.

Review in five bounded batches: **T1** is all 19 publisher-test BENIGN images, then **T2–T5** are 16 publisher-train BENIGN images each, ordered by strongest pixel correlation. The [T1 sheet 1](../analysis/nine_class_recovery/review_sheet_01.jpg) and [T1 sheet 2](../analysis/nine_class_recovery/review_sheet_02.jpg) show the 19 pairs in review-plan order. A reviewer should compare full-resolution originals where necessary, not infer identity from the sheet alone. The proposed decision in every row is **hold for visual review; exclude the binary row only if the same photograph is confirmed**, while retaining the HAM diagnosis. If a pair is different but plausibly the same lesion, record that separately for grouping/quarantine; if distinct, record the evidence and keep eligibility provisional. Preserve publisher test membership in every outcome. Do not bulk-reject by correlation and do not mark assistant/automated inspection as human adjudication.

The 19 T1 binary paths and strongest HAM candidates are fully source-qualified in the CSV. The T1 basenames, in review order, are `802, 1646, 678, 1191, 575, 1642, 1018, 1074, 61, 1393, 1342, 670, 559, 878, 1297, 1443, 311, 912, 532` (all `.jpg` under `data/isic/data/test/benign/`). All 19 strongest candidates are HAM `nv`, with pixel correlation **0.99664667–0.99892455**. Their publisher-test boundary must remain protected even if another source is added.

Any candidate requires license review, image-ID and visual overlap screening, patient/lesion grouping, and a label-scope decision before a count can be assigned to the adapted BENIGN or MALIGNANT category.

ISIC 2020 is a **candidate source**, not an approved merged dataset. Its publication documents patient-centric collection and clinical confirmation; that improves provenance over Fanconic. It also changes the source distribution, class balance, possible malignant label scope, and likely acquisition cues. The seven HAM `dx` labels remain untouched. BENIGN/MALIGNANT would remain **source-defined broad outcomes** in a nine-way output, not mutually exclusive diagnoses across datasets. Any final paper comparison must report per-source and per-class metrics, not only overall accuracy.

## 4. Two nine-class routes

| | A. Original-source nine-class reconstruction | B. Verified-additional-source nine-label adaptation |
| --- | --- | --- |
| Paper fidelity | Preserves HAM10000 + the cited Fanconic source family, nine output names, intended architecture, and verified paper preprocessing/training settings. Current local tree matches Fanconic v4 filenames and sizes. | Preserves nine output names and intended EG-VAN architecture and paper-derived methodology, while **explicitly changing** the binary data source/composition. |
| Expected eligible counts | HAM 10,015 source entries; binary **at most 83 BENIGN + 845 MALIGNANT** after current proposed exclusions. If all 83 strongest benign candidates prove same HAM photographs, BENIGN becomes **0**. The binary counts remain provisional. | HAM 10,015 plus only **verified unique, label-compatible** additional binary entries. No eligible addition count can be stated before source metadata, image overlap and clinical label-scope checks. |
| Leakage and grouping | 2,365 confirmed binary HAM-photo copies proposed out; 425 priority pairs still unresolved. Publisher-test boundary must be protected. Binary patient IDs unavailable; no patient independence claim. | Screen additional images against HAM, Fanconic and one another; use source patient/lesion IDs where provided, plus confirmed photo relations. Do not combine source test and training or trust an unlabeled official test. |
| Evaluation feasibility | **Currently blocked.** Publisher-test BENIGN upper bound is 19, all with very strong HAM candidate relations. Even after a version-4 match, the paper's actual image assignments and split remain unknown. | **Conditional research adaptation.** ISIC 2020 has enough nominal source images to investigate, but no genuinely new eligible count or compatible final class balance is verified. A new protected test and source-stratified evaluation would be required later. |

The project target of at least 95% leakage-audited internal accuracy is a future measurement goal, **not** a reason to change inclusion rules, tune the test set, or claim a guaranteed result. Neither route has a valid final manifest or split now. Image quality assessment, uncertainty estimation and external validation remain downstream research stages after a defensible nine-class data protocol and model reconstruction.

## 5. Local and historical code

Current `src/nine_class_similarity_audit.py`, `src/nine_class_overlap_review.py`, and `src/nine_class_overlap_completion.py` already provide candidate retrieval, SHA-256 and pixel evidence, transitive grouping, exclusion proposals, batched screening and contact-sheet rendering. The T1 contact sheets reused `contact_sheets` from the completion module; the 83-row queue is a read-only aggregation of existing CSVs. `src/preprocessing.py` has paper-informed hair/Gray World/Retinex functions with explicit local numerical choices. `src/dataset.py`, `src/build_splits.py`, `src/train.py` and `src/evaluate.py` remain seven-class/HAM-oriented and would require separate nine-class work **after** this gate. `src/models/egvan/egvan.py` can accept nine outputs.

Historical GitHub Stage4b/c/d utilities were previously inspected in the protocol review. Stage4c's contact-sheet idea is already covered locally; Stage4b/d depend on seven-class historical split artifacts and do not solve Fanconic provenance or the nine-class source problem. **No historical code file is required or restored.**

## Stage 3D decision and next action

Proceed with a **nine-class recovery route**. Give priority to the bounded T1–T5 BENIGN review and a request for EG-VAN authors' exact binary package/version, image membership, split and duplicate policy. The metadata match to Fanconic v4 removes much package-structure uncertainty but does not answer those scientific questions. If visual adjudication eliminates the remaining BENIGN class, Option A cannot yield a leakage-controlled local nine-class evaluation; evaluate Option B using a source such as official ISIC 2020 only after original binary labels, rights, nonoverlap and source-conditioned task meaning are accepted. No dataset download or final split is authorized by this report.
