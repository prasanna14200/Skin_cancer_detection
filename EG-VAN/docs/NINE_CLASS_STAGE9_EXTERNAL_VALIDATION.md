# Stage 9: external-validation infrastructure

Date: 2026-10-22. This stage prepares a frozen-model external evaluation workflow for the fixed source-defined order `AKIEC, BCC, BKL, DF, MEL, NV, VASC, BENIGN, MALIGNANT`. **No external dataset, approved nine-class cohort, trained checkpoint or independent validation result exists.** All executed tests used temporary synthetic images, labels, logits and a tiny model. The software does not approve source provenance, label compatibility or patient independence by itself.

## External source and manifest contract

The [external protocol module](../src/nine_class_external_protocol.py) requires one row per source-qualified image with `source_dataset`, `source_version`, source-root-relative `image_path`, optional `source_image_id`, optional `patient_id` and `lesion_id`, an explicit `identifier_namespace`, `original_clinical_label`, proposed `target_label`, `mapping_status`, `mapping_justification`, original-image `sha256`, `source_license`, `permitted_use_status`, `overlap_status`, `overlap_decision_reference`, and `eligibility_status`. Empty patient/lesion IDs remain **unknown**. Numeric filenames never become invented patient IDs. Source and version must be documented; image-level rights must be reviewed before `PERMITTED_FOR_RESEARCH_EVALUATION` is asserted.

Mapping statuses are `EXACT`, `CLINICALLY_JUSTIFIED_NONIDENTICAL`, `UNSUPPORTED`, and `UNKNOWN`. Only the first two can be approved for evaluation, and each needs a written justification tied to the source's original clinical definition. A broad `MALIGNANT` or `BENIGN` target is **not** inferred from melanoma, nevus or another HAM diagnostic label. Unsupported or unknown mappings can remain in a source inventory as `EXCLUDED` or `QUARANTINED`; they cannot enter the approved evaluation subset. A non-identical mapping requires specific clinical review and, before direct internal/external comparison, a further comparability justification. No dataset is presumed to contain all nine supported labels.

Candidate sources must provide a stable version and original image files, label-definition and collection-method documents, usage rights, and preferably image-level IDs plus patient/lesion linkage and acquisition context. Without those records, broad label comparability, patient independence and evaluation rights remain uncertain. The current [dataset-resolution decision](NINE_CLASS_STAGE6_DATASET_RESOLUTION.md) documents why the Fanconic source and possible alternatives are not yet an approved nine-class cohort.

## Overlap screening and adjudication

`screen_external` verifies every external image's SHA-256, checks exact byte equality against the Stage 4 internal inventory, and reuses the [Stage 3 pHash/dHash fingerprint implementation](../src/nine_class_similarity_audit.py) to retrieve candidates at Hamming distance ≤6. It also flags matching nonempty lesion/patient identifiers **only within an explicitly matching identifier namespace**; coincident strings from unrelated sources are not treated as a patient match. The screen records associated Stage 3I pair IDs when an internal candidate appears in that evidence. It writes `overlap_candidates.csv` and `overlap_report.json` to a new directory, including input hashes and per-image status. No images are copied or changed.

`EXACT_HASH_OVERLAP` and matching verified-namespace identifiers block evaluation. `POSSIBLE_PHOTO_OVERLAP` remains quarantined until an independently documented `REVIEWED_DISTINCT` decision is supplied; pHash/dHash alone are retrieval heuristics, not proof of either identity or distinctness. A `NO_CANDIDATE_FOUND` result also does **not** certify independence. Missing patient/lesion IDs are explicitly reported as `NO_CANDIDATE_FOUND_IDENTITY_UNKNOWN`. Crops, color changes and source-specific processing can evade the retrieval threshold; a later review may use the Stage 3 geometric and visual tools. The approval must acknowledge unknown-identity limits and reference the actual review record.

Future preparatory command after a candidate source has been obtained and documented, **without approving any row**:

```powershell
python src/nine_class_external_protocol.py --external-root PATH_TO_EXTERNAL_SOURCE --manifest PATH_TO_EXTERNAL_MANIFEST.csv --output-dir analysis/nine_class_stage9/NEW_OVERLAP_SCREEN
```

The external approval JSON must record a real reviewer and UTC date, source-rights, label-mapping, overlap-review and preprocessing references, an explicit frozen external-test declaration, and SHA-256s for the external manifest, overlap report, internal inventory, frozen checkpoint and Stage 4 preprocessing configuration. `synthetic_fixture` approvals are refused by the production path. Approval fields are a traceability gate; a fabricated declaration would still be scientifically invalid and is outside what code can authenticate.

## Frozen checkpoint evaluation

The [evaluation runner](../src/nine_class_external_evaluation.py) first validates the approved **internal** Stage 6 cohort and the run-provenance hashes, then the external manifest/approval/screen and current external image bytes. It requires the checkpoint's exact nine-label order, 384-pixel input and Stage 4 preprocessing-configuration hash in both the run record and checkpoint. Stage 6 now records that hash for future runs; an older checkpoint without it is rejected for external validation. Its default model is the Stage 5 EG-VAN factory. The trusted, hash-bound local checkpoint is loaded strictly; the model runs in evaluation mode under `torch.inference_mode()`. The Stage 4 deterministic preprocessing path uses `train=False`. There is no optimizer, gradient update, temperature fit or test-threshold selection. A new output directory holds source-qualified predictions, nine probabilities, confidence/entropy, raw-image IQA proxies, a quality-group table, metrics and provenance. The runner refuses an existing output directory and rechecks original image hashes after inference.

Future command, **only after an eligible internal split, trained checkpoint and external approval exist**:

```powershell
python src/nine_class_external_evaluation.py --internal-split PATH_TO_APPROVED_INTERNAL_SPLIT.csv --internal-approval PATH_TO_INTERNAL_APPROVAL.json --internal-inventory PATH_TO_INTERNAL_INVENTORY.csv --external-root PATH_TO_EXTERNAL_SOURCE --external-manifest PATH_TO_EXTERNAL_MANIFEST.csv --external-approval PATH_TO_EXTERNAL_APPROVAL.json --overlap-report PATH_TO_OVERLAP_REPORT.json --checkpoint PATH_TO_FROZEN_RUN/best.pt --output-dir analysis/nine_class_stage9/NEW_EXTERNAL_EVALUATION
```

The Stage 7 [tonal-change finding](NINE_CLASS_STAGE7_IQA.md) still requires preprocessing review before genuine external inference. The external implementation reproduces the current Stage 4 path for traceability; it does not claim that processing improves diagnostic information.

## Metrics and comparisons

The model always retains **nine output columns**. If approved external targets cover all nine labels, the runner can report full nine-class accuracy and macro/weighted F1. If only a subset is supported, it labels the result `supported_label_subset`, reports **subset accuracy** and supported-class macro/weighted F1, and leaves `full_nine_accuracy=null`. The nine-by-nine confusion matrix still exposes predictions into unsupported classes. Per-class support and recall for absent targets are null/zero as appropriate, and low support is warned about. Calibration metrics are withheld below 100 labeled images as a conservative reporting rule; larger samples still require inspection and have no guaranteed statistical precision. Raw-image quality-group tables mark groups under 20 as unstable. Confidence and predictive entropy follow Stage 8. No label is silently mapped or removed from the model.

The comparison helper normalizes actual Stage 6 internal-test and Stage 9 external report schemas. It requires the same frozen checkpoint, exact nine-class order, all-nine support, matching preprocessing configuration and compatible label meaning. It returns a **not-comparable** decision for a subset external report or a non-identical mapping without a comparison-specific justification. Where comparable, it prepares changes in accuracy, macro F1 and per-class recall, plus ECE, confidence and mean raw brightness only when both reports contain those measures. Missing measures remain null. Source differences and uncertainty must accompany any paper table. These descriptive differences do not establish causality or deployment readiness.
