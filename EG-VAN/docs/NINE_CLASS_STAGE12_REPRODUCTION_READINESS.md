## Training-system verification and decision

The [Stage 6 runner](../src/nine_class_training.py) constructs `build_nine_class_egvan()` with **nine raw logits** and rejects a changed class order/config. The [cohort validator](../src/nine_class_protocol.py) requires approved rows, unchanged source fields and image SHA-256, approval/split/inventory hashes, nine train and validation labels, no known cross-split SHA/overlap/lesion/patient groups, and publisher-test separation. Full training additionally requires a frozen protected test containing all nine labels. This mechanical gate cannot infer absent patient IDs or verify the truth of a human approval statement. No production `analysis/approved_nine_class/approved_split.csv` or `approval.json` exists.

The [Colab notebook](../notebooks/nine_class_colab_training.ipynb) checks pinned runtime/GPU, config, approved files and the production cohort gate **before** reading an approved validation image or constructing the model. Its validation-data smoke and batch-one GPU inference are gated; `RUN_TRAINING=False` and other execution flags remain false. It prints commands only after approval succeeds. The preflight reports actual free VRAM and a roughly 886 MiB weights/gradients/Adamax-state estimate **before** activations and overhead; peak VRAM is unmeasured. The candidate config uses microbatch 4 with 8 correctly sample-weighted accumulation steps, nominal effective batch 32; BatchNorm sees at most four samples per forward, and possibly fewer in the final microbatch. Accumulation does not aggregate BatchNorm statistics across microbatches. If training OOMs after a future approval, use a new versioned config and new run rather than silently changing a resumable run.

The raw-resize preprocessing hash is recorded with config, split, inventory and approval hashes in run provenance and each checkpoint. Resume uses only the matching run's `last.pt`, restores optimizer/scheduler/scaler state and starts after its last complete epoch; `best.pt` is for evaluation. The notebook's run root is on mounted Drive. The runner's checkpoint file is atomically replaced after each completed epoch, although a disconnection mid-epoch loses that partial work. Final test evaluation has a separate explicit flag and must wait for predeclared final assessment. Stage 6 has no bounded step-count training-smoke CLI; this is an additional command-design task **only after** a real approved cohort exists. A batch-one inference smoke is available now *only behind* the same cohort gate.
