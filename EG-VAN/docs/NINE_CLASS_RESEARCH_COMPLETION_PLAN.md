## 1. Original experiment: what the paper establishes

The local paper's article pages **72862–72863** say seven HAM10000 diagnoses were combined with a two-class malignant/benign collection, citing [45] and [54]. Table 2 reports **13,312 original images**: 10,015 HAM10000 and 3,297 binary (1,800 BENIGN, 1,497 MALIGNANT). It lists **1,332 original test**, **11,980 original train**, and augmented-image counts by class. Its binary source column says **“ISIC 2017”**. The paper also says its enlarged train set had 37,883 images and validation 6,686, including augmented images. Table 2's augmented column sums to **34,554**, which does not transparently reconcile with those enlarged train/validation totals. It does not give image-level manifests, split seed, augmentation lineage, the exact two-class archive version, or a mapping to original ISIC IDs. Table 2 implies approximately 10% original-image testing per class (benign 180 and malignant 150, after rounding), but not which images were selected or whether related lesions were separated.

**Source-name conflict requiring author clarification:** [official ISIC 2017 Task 3](https://challenge.isic-archive.com/landing/2017/44/) has 2,000 training images across melanoma, nevus and seborrheic keratosis, with image IDs and two related binary challenge tasks; the [Archive's pinned ISIC 2017 collections](https://api.isic-archive.com/collections/?doi=true&official=true&order=asc&sort=name) list 2,000 train, 150 validation and 600 test. That does **not directly identify** the paper's 3,297-image BENIGN/MALIGNANT pool. Earlier [recovery evidence](NINE_CLASS_DATASET_RECOVERY_PLAN.md) linked the counts and cited reference [45] to the [Fanconic Kaggle collection](https://www.kaggle.com/datasets/fanconic/skin-cancer-malignant-vs-benign), and found a strong **filename/byte-size** match between local files and the then-listed Fanconic v4 package. This is circumstantial package evidence, not a remote per-file checksum, clinical-label verification or proof that EG-VAN used v4. Kaggle's metadata endpoint was not accessible for a fresh check during this review; the 2026-10-19 metadata record is retained as prior evidence. Reference [54] does not supply the missing image list in the available record. The table's “ISIC 2017” may be a loose upstream attribution or a different source; **neither interpretation is verified**.

The local canonical Fanconic tree has the same 1,800/1,497 labels but a publisher **80/20** folder partition: BENIGN 1,440 train/360 test, MALIGNANT 1,197 train/300 test. The paper's Table 2 lists BENIGN **1,620/180** train/test and MALIGNANT **1,347/150**. Equal totals therefore do not reconstruct the paper's test set. There is no local archive receipt, binary-source ISIC-ID map, patient/lesion IDs, image-level license file, author split manifest, author code/weights, or author prediction table. A targeted search of the paper, local supplementary files and public indexed results located no author-provided repository or checkpoint; that is **not proof none exists**. Request them using the [Stage 12 questionnaire](NINE_CLASS_STAGE12_REPRODUCTION_READINESS.md).

The nine outputs mix seven specific HAM diagnoses with two broad binary-source labels. A HAM nevus can clinically be benign while a Fanconic BENIGN image is assigned a separate output; source identity can become a shortcut. No HAM diagnosis is relabeled as BENIGN or MALIGNANT here. Table 2's printed row order differs from the repository's frozen class-index order; the paper does not state output indices, so no exact index mapping is inferred from row order. The local model architecture is paper-informed rather than exact: [Stage 5](NINE_CLASS_STAGE5_ARCHITECTURE.md) records unresolved feature taps and attention/fusion details. [Stage 12](NINE_CLASS_STAGE12_REPRODUCTION_READINESS.md) records optimizer/scheduler and preprocessing deviations, including the paper's stated learning-rate patience 1 versus local config 2.

The **minimum technical** addition is enough documented, supported BENIGN cases/groups for nonempty train, validation and frozen protected test, with the nine-class gate satisfied in all three; the current protected-test shortfall is **at least one independently eligible BENIGN group** and likely many more for a meaningful estimate. One test case would yield an unusably coarse class estimate. Predeclare a precision/power target before fixing the required test-group count. Retained MALIGNANT cases and any new malignant class also need the same compatibility review.

## 5. Colab execution plan after a real cohort decision

The [existing notebook](../notebooks/nine_class_colab_training.ipynb) and [Colab guide](NINE_CLASS_COLAB_TRAINING.md) remain the gate; no executable **training** command is released for today's unapproved cohort. The notebook's training and final-test flags remain false. The [versioned config](../config/nine_class_training_colab_2026_07.json) selects conservative `raw_resize_imagenet_v2`, fixed nine-logit head/order, AMP only on CUDA, and microbatch 4 × accumulation 8 (nominal effective batch 32). The [pinned dependencies](../config/requirements_colab_2026_07.txt) are for the named Colab runtime, which must be available and checked when actually used. BatchNorm observes each microbatch, including a possibly smaller last one; accumulation does **not** reproduce batch-32 BatchNorm statistics. The estimated 886 MiB for parameters, gradients and Adamax buffers excludes activations, CUDA workspace and allocator overhead; actual peak is unknown.

1. **Repository synchronization:** package the **current** uncommitted Stage 4–12 code, config, tests and documentation as a versioned, hashed snapshot for Drive. Cloning the historical GitHub repository alone would miss local uncommitted work. Do not upload raw images until their research-use and Drive-storage rights are checked. Record the snapshot hash and runtime versions.
2. **GPU and dataset mount:** use the notebook's pinned-dependency/runtime check and `nvidia-smi`; mount Drive with original images, versioned inventory, approved split/approval and persistent run directory at one stable root. Verify image SHA-256 and publisher-test boundary before any model construction. No data or pretrained weights are downloaded automatically.
3. **Preflight:** run the Stage 6 `--validate-only` gate via the notebook. Confirm all nine classes in train/validation and frozen test, approved statuses, exact/overlap/lesion/patient grouping, rights references and frozen raw-preprocessing hash. The nine-label config and image decode must pass. No command is emitted for an unapproved cohort.
4. **Batch-one training smoke:** the notebook currently performs an **inference-only** approved-validation batch-one smoke. Stage 6 has **no bounded training-smoke CLI**; add a gated one-step forward/backward/optimizer mode using its existing loss/loader before claiming this step complete. Use one approved **training** image, write only a separate smoke artifact, never select a checkpoint from the smoke, and leave protected test untouched. A one-sample BatchNorm pass may be noisier or fail at a 1×1 feature; test it and record behavior rather than assuming success.
5. **Full training and resume:** only after smoke and memory measurement, run the Stage 6 runner through the notebook's explicit `RUN_TRAINING` opt-in. Start with the frozen microbatch/effective-batch config; on OOM choose a **new config and new run**. Drive stores `run_provenance.json`, `history.csv`, `last.pt`, `best.pt`; resume only matching `last.pt` with unchanged config/split/inventory/approval/preprocessing hashes. Disconnection mid-epoch loses that partial epoch. Select `best.pt` using validation loss only.
6. **Internal evaluation:** run `src/nine_class_evaluation.py` on validation after training. Run protected test once, with `--final-test`, after checkpoint and all analysis choices are frozen. Keep class supports and uncertainty intervals alongside aggregate metrics; do not target or guarantee the paper's 98.20%.
7. **IQA and uncertainty:** generate deterministic original-image IQA with `src/nine_class_iqa.py` for the full approved validation coverage; join Stage 6 predictions using `src/nine_class_iqa_performance.py`. Run `src/nine_class_stage8_analysis.py` on validation for entropy, margin, ECE and selective-risk exploration. Stage 8 **cannot fit production temperature scaling yet**: it needs a separate frozen calibration partition and logits artifact. The Stage 7 sample selector currently excludes publisher-test images, so protected-test IQA association additionally needs a gate-preserving approved-test coverage path before it can run. Never fit thresholds or calibration on test.
8. **External validation:** only after an independent, rights-cleared source has a frozen clinically justified mapping and overlap review, use `src/nine_class_external_protocol.py` and `src/nine_class_external_evaluation.py`. A binary-only external source cannot automatically support a full nine-label accuracy; the runner labels supported-class subset results separately. No external dataset or approval exists today.

The post-approval CLI interfaces are `src/nine_class_training.py`, `src/nine_class_evaluation.py`, `src/nine_class_iqa.py`, `src/nine_class_iqa_performance.py`, `src/nine_class_stage8_analysis.py`, `src/nine_class_external_protocol.py`, and `src/nine_class_external_evaluation.py`. Their precise flags and guarded future examples are in [Stage 6](NINE_CLASS_STAGE6_TRAINING_READINESS.md), [Stage 7](NINE_CLASS_STAGE7_IQA.md), [Stage 8](NINE_CLASS_STAGE8_UNCERTAINTY.md) and [Stage 9](NINE_CLASS_STAGE9_EXTERNAL_VALIDATION.md).
