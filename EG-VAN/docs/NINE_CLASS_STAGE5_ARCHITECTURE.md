# Stage 5: nine-class EG-VAN architecture and synthetic verification

## Scope and source

This audit used the local 23-page IEEE Access article, *EG-VAN: A Global and Local Attention-Based Dual-Branch Ensemble Network With Advanced Color Balancing for Multi-Class Skin Cancer Recognition*, DOI [10.1109/ACCESS.2025.3561240](https://doi.org/10.1109/ACCESS.2025.3561240), especially Figure 3, Table 1, Figure 4, and equations 16–30 on article pages 72858–72862. The local PDF is at `E:/Cancerdetection/EG-VAN_A_Global_and_Local_Attention-Based_Dual-Branch_Ensemble_Network_With_Advanced_Color_Balancing_for_Multi-Class_Skin_Cancer_Recognition.pdf`. Existing module tests were read and rerun; passing shapes alone were not taken as paper evidence. No weights were downloaded, no data images or split records were read, and no training or checkpoint write occurred.

## Paper-to-code mapping

| Component | What the paper specifies | Current code and verification | Status / remaining choice |
| --- | --- | --- | --- |
| Dual backbones | Pre-trained EfficientNetV2S plus modified ResNet50; Table 1 lists their stage widths and depths. | `efficientnet_branch.py` uses torchvision EfficientNetV2-S stages; `modified_resnet50.py` uses torchvision ResNet50 blocks. Its SCGA follows 256/512-channel stages, and non-local blocks follow 1024/2048-channel stages. Stage widths and 384px tensor shapes were verified. | Backbone families and ResNet placement **match**. The synthetic test deliberately uses random initialization; the paper's pre-training is not reproduced. |
| EfficientNet taps | Figure 3 shows paired intermediate features at several levels; Table 1 gives stage channels, but does not uniquely enumerate the four MFF tap indices. | Feature indices `(2,3,5,7)` produce `(48,64,160,1280)` channels. | Four taps are a **local interpretation** of Figure 3 and Table 1. Alternate pairings cannot be ruled out from the article. |
| SCGA spatial path | Figure 4 and prose describe 1×1 convolutions with 64, 16, 8, then 1 mask channel, dilation 2 at the 16-channel layer, ReLU then sigmoid; global average of the mask, element-wise refinement and channel expansion. | `spatial_attention.py` implements that sequence, with a fixed all-ones channel expansion and a parallel learned 1×1 input projection shown in Figure 4. | The flow is **supported**. The paper's prose calls the channel-expansion weights fixed, while the diagram also shows a separate input projection; the exact role of that projection is not fully specified. Dilation 2 on a 1×1 kernel has no enlarged receptive field. |
| SCGA group path | Equations 16–22 split channels into groups, compute width/height mean and max, use separate 1×1 convolutions with sigmoid scores, add horizontal/vertical scores, apply a final sigmoid, multiply each group and concatenate. | `scga.py` performs these operations after the spatial path; group-attention shapes and gradients pass. | Mechanism **matches the described operations**. Group count `8` is a local choice; no count is specified in the paper. |
| Non-local refinement | Equations 23–28 describe embedded-Gaussian query/key/value attention, softmax normalization, a learned output projection, residual addition and spatially reduced keys/values. | `non_local.py` implements this at the last two ResNet stages. A zeroed projection gives exact identity output in the residual-path test. | Core mechanism **matches**. Channel reduction `2`, key/value average-pool stride `2`, and projection initialization are local choices because numerical settings are not given. |
| Multi-feature fusion | Figure 3(A), §III-C.5 and equations 29–30 put spatial attention on EfficientNet features, group mean/max attention on ResNet features, concatenate, apply stride-2 separable convolution, batch normalization, then SCGA. Figure 3 connects successive MFF blocks and concatenates final routes before global average pooling. | `mff.py` implements depthwise-plus-pointwise stride-2 convolution, BN and SCGA, with a serial carry. `egvan.py` resizes and concatenates four MFF outputs plus both terminal branch maps, applies a 1×1 aggregate projection, global average pool and dense classifier. The carry and all four scales receive gradients. | Main sequence **matches**. Fusion width `128`, bilinear alignment, carry resizing, terminal-route aggregation width and exact tap-to-MFF pairing are local choices. The paper does not supply enough dimensions to identify them uniquely. |
| Classifier | Figure 3 shows GAP, classification and softmax for probabilities. | `egvan.py` returns dense-layer **raw logits**. The caller may apply softmax only for inference; a logit-based loss must receive the unnormalized output. | Explicit **loss-interface adaptation** required by this Stage 5 contract. |

The paper also states that modified ResNet50 retains the same parameter count as the original. The described SCGA and non-local modules contain learned convolutions, and the current implementation's modified ResNet body has **34,393,794** parameters versus **23,508,032** for the unmodified torchvision ResNet50 body without its 1,000-way FC head. This is a material quantitative mismatch with the prose claim. No paper-reported parameter total or exact reduction recipe resolves it, so this implementation is **paper-informed, not a verified exact weight-level reproduction**. Do not conceal the difference by counting different heads or silently dropping attention modules.

## Nine-class construction and shape flow

`build_nine_class_egvan()` in `src/models/egvan/egvan.py` creates an `EGVAN(num_classes=9)` with no pretrained-weight request by default. The legacy `EGVAN()` seven-output default is retained for old experiments. The fixed Stage 4 label order is `AKIEC=0, BCC=1, BKL=2, DF=3, MEL=4, NV=5, VASC=6, BENIGN=7, MALIGNANT=8`. The architecture never assigns these names internally; the dense output index follows this data contract.

| Synthetic tensor at batch 1 | Shape |
| --- | --- |
| RGB input, NCHW | `1×3×384×384` |
| EfficientNet feature taps | `48×96×96`, `64×48×48`, `160×24×24`, `1280×12×12` |
| Modified ResNet feature taps | `256×96×96`, `512×48×48`, `1024×24×24`, `2048×12×12` |
| MFF outputs after stride 2 | `128×48×48`, `128×24×24`, `128×12×12`, `128×6×6` |
| Aligned concatenation, then 1×1 aggregate projection | `128×6×6` |
| Global average pool, dense head | `1×9` raw logits |

The model's input normalization is handled outside the architecture by the Stage 4 loader. Pretrained ImageNet normalization and any future checkpoint selection must be frozen with the eventual training protocol. The local model factory does not invoke torchvision weight downloads unless a caller explicitly requests pretrained branches.

## Synthetic verification and resources

`python src/nine_class_stage5_probe.py` ran once on CPU with seed 42, one synthetic `384×384` RGB input, no pretrained weights, and two PyTorch CPU threads. The [probe record](../analysis/nine_class_stage5/architecture_probe.json) contains all intermediate shapes, parameter counts and finite-gradient checks. Forward produced finite `(1,9)` logits. A backward pass from a synthetic scalar reached the input, both backbone stems, SCGA spatial/group parameters, non-local query/project, first and later MFF paths, aggregate projection and nine-class head with finite gradients. This proves computational connectivity for the tested shape; it says nothing about accuracy or optimization quality. Separate tests verified deterministic random initialization under an explicit seed, residual identity when the non-local projection is zeroed, attention/fusion dimensions and preservation of the legacy seven-output default.

Total and trainable parameters: **58,087,667**. Breakdown: EfficientNet branch **20,177,488**; modified ResNet branch **34,393,794**; four MFF blocks **3,023,704**; aggregate projection **491,520**; nine-class head **1,161**. Float32 parameter storage is about **221.6 MiB**. Parameters plus gradients require about **443.2 MiB** before activations, optimizer state and framework overhead. An Adamax-style training state would add roughly two more parameter-sized float32 buffers, bringing these four persistent components near **886.3 MiB** before activations; this is an estimate, not measured peak memory.

The probe demonstrated that a batch-one CPU forward and backward are feasible in the current runtime. This Windows environment reports about **7.68 GiB physical RAM**, 12 logical CPUs and **no CUDA device available to PyTorch**. Free RAM is dynamic; no latency or GPU-memory benchmark was made. Full 384px training would likely need a supported GPU and a separately measured batch/memory plan; this Stage 5 run did not start training.

`python -m pytest tests/test_nine_class_stage5.py tests/test_egvan.py tests/test_egvan_paper_alignment.py tests/test_scga.py tests/test_non_local.py tests/test_mff.py tests/test_nine_class_shape_contract.py -q` returned **14 passed**. Torchvision warned that its optional `torchvision.io` image extension could not load on this Windows installation; model construction and tensor tests passed and did not use that extension.

## Stage 6 gate

The **architecture interface and synthetic shape/gradient checks are ready** for further engineering or paper-author clarification. Full nine-class training and internal evaluation are **not ready**: Stage 4 has no approved eligible nine-class cohort or protected test split, all provisionally retained BENIGN entries have unresolved AI-supported HAM overlap, and the Fanconic source/version and patient identity limits persist. If Stage 6 means model training, its gate is **NO** until those data decisions are resolved. Further architecture work should seek the authors' exact tap/fusion widths, SCGA group count, non-local reduction, aggregation details, parameter count and pretrained checkpoint policy. No accuracy claim follows from the synthetic probe.
