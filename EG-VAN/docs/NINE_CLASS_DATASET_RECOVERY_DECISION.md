# Nine-class dataset recovery decision and Colab compatibility

Date: 2026-10-24. **Current decision: DATASET_BLOCKED.** The nine output names remain `AKIEC, BCC, BKL, DF, MEL, NV, VASC, BENIGN, MALIGNANT`. The [T4 training configuration](../config/nine_class_training_t4_v1.json), Stage 6 cohort gates, preprocessing options, architecture and research-feature code remain in place. Two small official 2020 metadata CSVs were obtained for an ID-only screen; no clinical image package was downloaded, and no label, reviewer decision, approval or split was changed.

## Colab runtime change

The [notebook](../notebooks/nine_class_colab_training.ipynb) no longer requires a literal PyTorch `+cu128` or torchvision `+cu128` suffix, nor one Python patch version. Its [compatibility helper](../src/nine_class_colab.py) requires CUDA availability, a CUDA-enabled PyTorch build, the required AMP interfaces and GPU capability, then constructs unweighted torchvision EfficientNetV2S and ResNet50 backbones. A small CUDA autocast matrix operation must produce finite output. This checks the interfaces used by EG-VAN without downloading weights or accessing images. The verified `torch==2.11.0+cu130` environment is eligible to pass these checks **if its installed torchvision is compatible**; torchvision's actual version and the probe result from that Colab runtime have not been supplied. A local CPU test verifies the helper's accept/reject logic with synthetic stubs; it is not a T4 runtime probe.

The notebook now selects the versioned **8 × 4** T4 config with frozen BatchNorm running statistics. `RUN_TRAINING`, resume, validation evaluation and final-test flags remain false. The existing approval and protected-test checks still stop the notebook before any clinical model run when files are missing or invalid. The separate Stage 6 runner's config, source-image and group safeguards were not relaxed. The pinned non-Torch requirements file was only corrected to describe the runtime check.

## Concrete alternative: official SIIM–ISIC 2020 training source

The [official ISIC Challenge data page](https://challenge.isic-archive.com/data/#2020) lists a fixed training release of **33,126 JPEG images**, [training metadata v2 with patient and lesion IDs](https://isic-archive.s3.amazonaws.com/challenges/2020/ISIC_2020_Training_GroundTruth_v2.csv), [training ground truth](https://isic-archive.s3.amazonaws.com/challenges/2020/ISIC_2020_Training_GroundTruth.csv), and an [official 425-pair duplicate list](https://isic-archive.s3.amazonaws.com/challenges/2020/ISIC_2020_Training_Duplicates.csv). The metadata v2 file (2,387,418 bytes) and duplicate list (11,500 bytes) were retrieved from these official URLs; the separate ground-truth CSV was unnecessary because v2 contains its label fields. The approximately 23 GB JPEG package was **not** downloaded. The [dataset descriptor abstract](https://pubmed.ncbi.nlm.nih.gov/33510154/) reports **584 histopathologically confirmed melanomas** among 33,126 dermoscopic images from 2,056 patients. The locally read v2 file has **32,542 benign and 584 malignant rows**, consistent with that total. These are source counts, **not** eligible nine-class counts.

The [metadata-only screen](../analysis/nine_class_dataset_recovery/metadata_screen_v2.json), produced by [reproducible code](../src/nine_class_metadata_screen.py), hashes the official CSVs and local HAM metadata. It found 33,126 unique official image IDs, 10,015 HAM image IDs, **zero exact ID intersections**, 425 official duplicate edges, and **32,120 connected components among the 32,542 benign rows**. All official rows have nonblank patient and lesion IDs; the ID-only BENIGN pool spans 2,055 patient IDs. The duplicate list has **eight links whose lesion IDs disagree**, so the duplicate edges and patient IDs must be reconciled before grouping. The detailed diagnosis is `unknown` for 27,124 official rows; the binary label does not confer a specific diagnosis. Zero shared IDs do **not** establish zero shared photographs or patients: source collections may reassign IDs, and Fanconic's numeric filenames have no verified bridge. The screened 32,542 rows and 32,120 components are upper bounds before photographic/label review; **approved eligible BENIGN remains zero**. The earlier `metadata_screen.json` is retained as a preliminary run; `metadata_screen_v2.json` adds component and conflict checks and is the decision evidence.

The official page publishes the aggregate SIIM–ISIC 2020 release under **CC BY-NC 4.0** and gives a required citation; the [license terms](https://creativecommons.org/licenses/by-nc/4.0/) permit sharing and adaptation subject to attribution and noncommercial use. This is a credible route for a noncommercial research study after confirming the planned use, attribution, image-level rights and any redistribution restrictions for selected records. It is not evidence that Fanconic or any mixed derivative has the same rights. The [2020 challenge task](https://challenge.isic-archive.com/task/56/) defines melanoma detection using patient context. Its challenge-defined negative label is **benign in a melanoma-detection task**, while Fanconic's folder `BENIGN` has no verified image-level clinical derivation. The alternative can therefore support a **clearly labeled source-defined BENIGN adaptation only after label review**; it cannot establish that the binary labels or the paper's nine-class task are identical. In particular, the 2020 positive class is melanoma and must not silently be relabeled as Fanconic `MALIGNANT` or HAM `MEL`.

The official 2020 challenge test set has no published ground truth on the data page, so it is **not** a ready labeled protected test here. Any proposed train/validation/calibration/test partition must come from eligible, labeled training images after source and overlap review; it must not reuse the current Fanconic publisher test for training. The metadata show enough distinct BENIGN patients to make a four-way partition numerically plausible, but the photographic overlap screen, usable group counts after adjudication and all-nine-class distribution have **not** been established.

| Dataset-blocked | Current HAM + Fanconic evidence only, with unresolved BENIGN photo relations and no approved protected test. | **Present status.** No training or final evaluation. |

Seven HAM diagnostic outputs and broad binary outputs are not mutually exclusive clinical diagnoses. Even if a new BENIGN pool is photographed independently, a classifier may learn acquisition/source differences, and a `BENIGN` output is not a universal synonym for every benign HAM diagnosis. Retain original labels and source indicators; report source-stratified and classwise results. Do not infer patient independence from absent Fanconic identifiers or assume that patient IDs from different source systems share a common namespace.

## Minimum acquisition, overlap and approval path

1. **Metadata-only screen completed.** Official v2 labels/IDs and duplicate pairs are hash-recorded in `metadata_screen_v2.json`; a separate ground-truth file would repeat label data already in v2. Record the official URLs, retrieval date and citation with the future cohort. The zero HAM ID intersection and 32,120 benign duplicate components are metadata observations, not clearance. Investigate the eight duplicate edges with inconsistent lesion IDs.
2. **Resolve label and source policy.** Specify which official 2020 ground-truth values qualify for the source-defined `BENIGN` output and whether any ambiguous diagnoses are excluded. Keep HAM's seven diagnoses and Fanconic's original labels unchanged. Decide whether the existing Fanconic `MALIGNANT` candidates can be retained after their own rights, identity and overlap review. Do not substitute 2020 melanoma into `MALIGNANT` by name alone.
3. **Acquire only needed original images after metadata review and rights sign-off.** From the official fixed JPEG release or documented archive records, acquire a bounded, preselected candidate set with original IDs and byte hashes. No bulk package download is needed at the metadata stage. Screen SHA-256, original ISIC-ID matches, perceptual similarity and independently reviewed difficult pairs against **both** HAM10000 and canonical `data/isic/data/`; link any confirmed same photographs or lesions. A nonmatching hash or absent shared ID does not prove independence.
4. **Confirm four-way feasibility before approval.** Group SIIM 2020 candidates by its verified patient and lesion IDs, official duplicate list and confirmed overlap links. Keep unresolved candidates quarantined. Include protected Fanconic source-test and HAM overlap groups in the boundary audit. Count eligible groups and images for each of the nine classes in train, validation, calibration and frozen test. Only then select an explicit seed/protocol and verify that no known group crosses partitions. The current Stage 6 schema accepts `train|validation|test`, so a separate calibration partition and its leakage/approval checks would need a **versioned protocol extension** before temperature fitting. Do not use validation or test as an undeclared calibration set.
5. **Record actual approvals.** Independent image review and source/rights evidence must support the approved eligibility ledger. Freeze the inventory, split and approval hashes with a meaningful BENIGN test count and all nine classes; retain exclusions and unresolved cases. Run the existing production validator and the new calibration-specific gate if calibration is part of the final protocol. Only after those pass may the disabled Colab training flag be considered.

The smallest next step for the modified route is a **bounded original-image pilot** selected from the documented 2020 benign metadata, after source-use sign-off, to test photographic overlap with HAM and canonical Fanconic. Keep the 19 disputed Fanconic BENIGN source-test records quarantined; they need not enter an alternative-source cohort. Independent review of those 19 and an author manifest remain necessary for a claim about the original-source route, and may proceed separately. The completed metadata screen cannot approve a cohort or supply image-level overlap evidence by itself.
